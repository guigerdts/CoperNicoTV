Objetivo: auditoría integral del pipeline de reproducción y corrección de los problemas de compatibilidad en streams IPTV reales con una solución GENERAL, extensible y segura (no un parche para FX). Ampliar compatibilidad SIN regresiones en los canales que ya reproducen (HBO y Cinecanal HD: READY).

## Specs

- S1 (evidencia física). «E7-T8 ya está integrado y dispone de CI 5/5. Se confirmó reproducción real de: HBO: READY. Cinecanal HD: READY. Audio y vídeo funcionales. Canales problemáticos: FX, identificador 1274: ERROR_CODE_IO_UNSPECIFIED. IllegalArgumentException. ProgressiveMediaSource. HTTP no disponible. Fallo aproximadamente en 1 segundo. La lista contiene URLs Xtream y aproximadamente 146.000 entradas. Estos dos errores NO demuestran que ambos streams tengan la misma causa. - S2 (auditoría). «Realizar una auditoría integral del pipeline de reproducción de CoperNicoTV» inspeccionando «SesionMedia3.kt, Configuración de ExoPlayer, DefaultMediaSourceFactory, DefaultHttpDataSource.Factory, FuenteHttpSeguimiento, ResolverRedirecciones, Selección de MediaSource, Extractores disponibles, Manejo de MIME y extensiones, User-Agent, Headers HTTP, Gestión de credenciales, Ciclo de vida del reproductor, Diagnóstico y clasificación de excepciones, Selección de audio y subtítulos, Gestión de buffer y errores de reproducción.» «Antes de modificar código, reconstruir el flujo real desde la selección del canal hasta la primera muestra de vídeo.»
- S3 (detección). «Diseñar una estrategia de detección basada en evidencia combinada: 1. Metadatos M3U. 2. Extensión de URL. 3. Parámetros Xtream. 4. MIME de respuesta. 5. Redirecciones HTTP. 6. Inspección segura de bytes iniciales cuando corresponda. 7. Reconocimiento del contenedor. 8. Disponibilidad de extractores y módulos Media3.» Contemplar «MPEG-TS. HLS / M3U8. MP4 / fMP4. MPEG-DASH / MPD. AAC. MP3. Otros formatos que el stack actual pueda soportar realmente.» «No depender únicamente de la extensión de URL. No asumir que toda URL sin extensión es MPEG-TS. No asumir que toda respuesta HTTP 200 contiene vídeo. No confundir una respuesta HTML de autenticación o bloqueo con un stream válido.»
- S4 (MediaSource). «Implementar una selección explícita y verificable de MediaSource» evaluando «HlsMediaSource. ProgressiveMediaSource. DashMediaSource. DefaultMediaSourceFactory cuando su detección automática sea suficiente.» «Evitar crear una arquitectura paralela innecesaria si Media3 ya proporciona la funcionalidad requerida. …No implementar fallback indiscriminado que pruebe todos los MediaSource a ciegas. Si una estrategia falla, permitir una alternativa únicamente cuando exista evidencia de que el formato alternativo es plausible. Preservar los parámetros HTTP y la seguridad de las solicitudes.»
- S5 (diagnóstico). «Ampliar el diagnóstico para diferenciar: Fallo DNS. Conexión. Timeout. HTTP 3xx. HTTP 401/403/404/429/5xx. MIME inesperado. Respuesta HTML. Contenedor no reconocido. Esquemas inicial/final. User-Agent. Código Media3. Excepción original y causa raíz. Duración. Intentos y reintentos.» «Nunca incluir URLs completas, contraseñas, tokens ni credenciales en informes o logs.» «El diagnóstico debe diferenciar un error de red de uno de contenedor o decodificación.»
- S6 (seguridad HTTP). «Preservar E7-T8.» Auditar «Redirecciones HTTP ↔ HTTPS. Redirecciones cross-domain. No reenvío de credenciales entre dominios. Protección contra downgrade HTTPS → HTTP. TLS y validación de certificados. User-Agent. Headers específicos de cada fuente.» «No desactivar validaciones TLS. No enviar credenciales a dominios de destino no autorizados. No debilitar las políticas de seguridad para conseguir que un canal reproduzca.»
- S7 (recuperación). «Implementar recuperación selectiva. Reintentar errores transitorios de red. No reintentar indefinidamente errores HTTP definitivos. No repetir solicitudes por errores de contenedor sin una estrategia alternativa justificada. Diferenciar errores de inicialización y errores durante reproducción. Evitar bucles de reconstrucción del reproductor. Mantener la posición y el estado cuando una recuperación sea segura. Los reintentos deben ser acotados y observables.»

No declarar compatibilidad con códecs o protocolos que no estén soportados por el stack real.»
- S10 (ejecución). «No detenerse en una auditoría documental. Después de demostrar las causas, implementar las correcciones justificadas.
